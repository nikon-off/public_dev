# План: Агент «teaching» для GigaCode на основе Superpowers

## Цель

Разработать полный пакет агента-преподавателя для GigaCode, который умеет:
- Объяснять код, архитектуры, концепции
- Проводить интерактивные уроки иCode Review с образовательной целью
- Адаптировать объяснения под уровень ученика
- Использовать Socratic method (вопросами направлять к ответу)

## Структура результата

```
.gigacode_vsc/
├── agent/
│   └── teaching.md              # Агент + системный промт
├── command/
│   ├── explain.md               # Команда: объяснить код
│   └── lesson.md                # Команда: провести урок
├── skills/
│   └── teaching/
│       └── SKILL.md             # Основной навык (системный промт)
│       ├── teaching-patterns.md # Паттерны объяснений (supporting)
│       └── anti-patterns.md     # Антипаттерны (supporting)
```

## Этапы реализации

### Этап 1: Изучение и анализ (Research)

1. **Изучить ключевые навыки Superpowers** для извлечения паттернов:
   - `skills/brainstorming/SKILL.md` — Socratic method, структурированные диалоги
   - `skills/test-driven-development/SKILL.md` — RED-GREEN-REFACTOR как метафора обучения
   - `skills/systematic-debugging/SKILL.md` — пошаговый процесс, фазы
   - `skills/writing-skills/SKILL.md` — структура SKILL.md, SDO, bulletproofing
   - `skills/using-superpowers/SKILL.md` — discovery rules, skill priority, red flags

2. **Извлечь общие паттерны** из Superpowers:
   - Структура frontmatter (name, description)
   - Pattern: Overview → When to Use → Core Process → Red Flags → Anti-Patterns
   - Rationalization tables
   - Bulletproofing против skipping
   - SDO (Skill Discovery Optimization) — description как trigger, не summary

3. **Изучить формат агентов GigaCode**:
   - `.gigacode_vsc/agent/*.md` — YAML frontmatter + системный промт
   - Поля: `description`, `mode`, `model`, `steps`, `hidden`, `color`, `permission`

### Этап 2: Проектирование SKILL.md (Навык «teaching»)

Создать `skills/teaching/SKILL.md` по структуре Superpowers:

```yaml
---
name: teaching
description: Use when explaining code, teaching concepts, conducting code reviews for learning, or creating educational content
---
```

**Разделы:**
1. **Overview** — что это, core principle (Socratic teaching + Superpowers discipline)
2. **When to Use** — симптомы/ситуации (код для объяснения, запрос урока, учебный code review)
3. **Teaching Levels** — адаптация под уровень (beginner, intermediate, advanced)
4. **Core Teaching Process** — пошаговый процесс:
   - Assess level → Explain conceptually → Show code → Ask questions → Verify understanding
5. **Socratic Method** — как задавать наводящие вопросы, не давать готовые ответы
6. **Explanation Patterns** — паттерны объяснений (analogies, step-by-step, before/after)
7. **Red Flags** — rationalization table (когда агент «сливает» ответ вместо вопроса)
8. **Anti-Patterns** — что НЕ делать (lecturing, skipping assessment, overwhelming)
9. **Code Review for Learning** — как проводить CR с образовательной целью

### Этап 3: Создание Supporting Files

1. **`teaching-patterns.md`** — коллекция паттернов объяснений:
   - Analogy-based explanation
   - Step-by-step walkthrough
   - Before/after refactoring
   - Concept → Code → Example pipeline
   - Zone of Proximal Development technique

2. **`anti-patterns.md`** — что избегать:
   - Lecture mode (слишком много информации сразу)
   - Answer dumping (готовый ответ без вопросов)
   - Level mismatch (объяснять beginner-у как advanced)
   - Context skipping (не проверять, что уже известно)
   - Over-optimization (refactoring ради refactoring, а не обучения)

### Этап 4: Создание агента GigaCode

Создать `.gigacode_vsc/agent/teaching.md`:

```yaml
---
description: Educational agent for explaining code, teaching concepts, and conducting learning-focused code reviews
mode: subagent
steps: 30
color: "#4CAF50"
permission:
  bash: allow
  edit:
    "**/*.md": allow
    "**/*.{js,ts,py,go,rs,java,cpp,c,h,rb,php}": allow
    "*": ask
---
[Системный промт, который включает:
- Инструкцию использовать superpowers:teaching перед любым объяснением
- RED FLAGS для дисциплины
- Базовые правила взаимодействия с «human partner»]
```

### Этап 5: Создание команд

1. **`.gigacode_vsc/command/explain.md`**:
```yaml
---
description: Объяснить код, функцию или концепцию в проекте
agent: teaching
---
Объяснить $ARGUMENTS. Адаптируйся под уровень ученика. Используй Socratic method.
```

2. **`.gigacode_vsc/command/lesson.md`**:
```yaml
---
description: Провести структурированный урок по теме
agent: teaching
subtask: true
---
Провести урок по теме $ARGUMENTS. Начни с assessment уровня.
```

### Этап 6: Тестирование (Pressure Scenarios)

Создать сценарии для проверки:
1. **Discipline test** — агент задаёт вопрос вместо того чтобы сразу дать ответ
2. **Level adaptation test** — агент адаптирует объяснение под beginner vs advanced
3. **Socratic test** — агент использует наводящие вопросы, не «сливает» решение
4. **Anti-pattern test** — агент не lectures, не overwhelming, не context-skipping

## Ключевые принципы (из Superpowers)

- **Socratic over lecturing** — вопросы → ответы, не наоборот
- **Assess before explaining** — проверь уровень, потом объясняй
- **Verify understanding** — убедись что поняли, прежде чем идти дальше
- **RED-GREEN-REFACTOR for teaching** — попробуй → проверь → улучши объяснение
- **Bulletproofing** — таблицы rationalization, red flags, prohibition tables
- **SDO** — description = когда использовать, НЕ что делает

## Зависимости

- Требуется доступ к репозиторию `obra/superpowers` (через webfetch)
- Требуется понимание структуры GigaCode (из loaded skill)

## Что НЕ делать

- Не копировать Superpowers дословно — адаптировать под teaching
- Не создавать проект-специфичные навыки — общий пакет
- Не превышать 500 слов в SKILL.md (token efficiency)
- Не использовать `@` syntax для cross-references (burns context)
